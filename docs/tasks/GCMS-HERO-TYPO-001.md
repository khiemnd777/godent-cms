## Implementation

- API parser accepts the optional config style only for Signature and a bounded optional title phrase only for homepage carousel slides. The phrase is plain text and must be one exact unique substring; a later title edit that removes it is rejected at save.
- The CMS editor offers a per-locale style selector, direct manual phrase entry, and an accessible “Dùng đoạn đang chọn” action from the slide title input. Clearing the phrase omits its key from the draft. Existing draft save/version and publish commands remain in use.
- The private preview passes the saved phrase and saved locale config to the shared Signature carousel. The public parser derives the phrase from the sanitized section snapshot and rejects an unpinned phrase in the resolved slide. The public config projection restores only the validated style after the existing 0060 sanitization of private navigation references.
- The Signature carousel renders escaped text and scopes the two editorial styles to homepage carousels. The default style retains its visual typography. The selected editorial mobile styles keep the supporting sentence visible and reserve room for portrait artwork.
- Independent xHigh review found two visual defects: the previous block-level leading title span forced a line break before the selected phrase, and rose editorial used Georgia instead of the design's DM Serif Display. The renderer leaves title text inline around one emphasized phrase. A later responsive review found a two-word emphasis split across lines at 390 px. The editorial-only outer phrase wrapper now keeps a short phrase together when it fits on an empty line; `max-width: 100%` allows a long phrase's inner text to wrap inside the heading without horizontal overflow. The CSS uses a fragment-aware background for the emphasis. The CMS help explains that editors select only the words to emphasize and that line wrapping responds to width. Rose uses locally bundled DM Serif Display Regular/Italic and a byte-identical copy of the existing OFL notice under `apps/website/app/fonts/`; warm and default retain their font choices.
- Independent re-review found a private/public parity defect: admin imports the shared Signature CSS, but the original `/fonts/` URLs resolved on each app's own origin and the website public proxy did not exempt that path. Copying fonts into both `public/` directories made the static parity test pass but a canonical-host website HTTP GET returned 503. The repair uses source-relative font URLs in the shared CSS so each Next build emits identical font bytes under its own `/_next/static/media/` path, which the website proxy already exempts. Unused `public/` copies were removed. The focused test checks both layout imports, CSS source references, font files and OFL notice; live canonical-host GETs of built CSS and both emitted fonts then passed on both apps. No origin-specific URL or proxy exception was added.
- The 0065 migration wraps current SQL content validation, config projection and new-locale blank-draft behavior. It does not rewrite historical publications. The blank-draft wrapper removes a copied highlight when a new locale title is blank.
- The established `scripts/lacvan-migrate.ts` accepts an explicit `--hero-typography` slice for only 0065 and freezes its SHA-256 checksum at `1c43700dcb2fb617f802274e7c729a115ae308e234ccfbf3bcbd261921095972`. Existing default/template, clock and search selections and the prior applied-checksum guard remain unchanged.
