### Resolver ownership and contract

Domains and public routing owns the registered normalized tenant-slug namespace and verified custom-host bindings to stable tenant/site identities. Registration and resolution must use a single explicit normalization/validation contract. Enforce normalized slug uniqueness and reserved platform/admin/API/static namespaces at the authoritative registry/data boundary, not only the UI. The project platform host cannot be claimed as a tenant custom host. The exact reserved strings, slug format/case/encoding rules and lifecycle/aliases remain to confirm before implementation; malformed or ambiguous selectors cannot fall through to a different tenant.

Input is the trusted-proxy-normalized request host and safely parsed path, plus the authoritative current mapping/eligibility registry. Untrusted forwarded headers, client tenant/site IDs, form hints or a referrer never override the resolved binding or private authorization. Do not double-decode or interpret an ambiguous path differently at the proxy, renderer and API boundaries.

| Entry / condition | Resolution and URL base |
| --- | --- |
| Platform host godent.vn, reserved platform/admin/API/static route | Dispatch only to its explicit platform namespace; never treat that prefix as a tenant slug |
| `godent.vn/<tenant-slug>/<site-page-path>` | Resolve the registered unique normalized slug to its active tenant/site; base path is `/<tenant-slug>`; remaining suffix is the site page path. Hostname alone is insufficient on this shared host. |
| Verified active custom host, `/<site-page-path>` | Resolve its current host binding to the same tenant/site; base path is empty (site root). The entire path is a site page path, not another tenant selector. |
| Unknown host/slug, unverified/inactive/removed binding or ineligible tenant/site | Deny public tenant resolution; do not fall back to a supplied tenant ID, another mapping or a guessed/default site |

The resolver returns a validated context: `tenant_id`, `site_id`, entry mode (platform path/custom host), validated entry origin, base path, site page path and mapping identity/revision. These are proposed contract field names, not an implemented API/schema. Publication/locale/resource reads validate that context and current eligibility. Private administration and preview still require current tenant/resource/action authorization; shared-origin paths or cookie path scope alone are not a tenant security boundary. Use the local origin table above and apply the approved S02 D10 session/CORS/CSRF handling; the production-only admin-origin proposal does not mandate local topology.

### Primary URL and page redirects

[ADR-004](decisions/004-primary-url-and-301-redirects.md) records approved option A. The Godent URL is initially primary and each eligible published page has an absolute same-language self-canonical there. Primary URL is a stable tenant-level choice, not an arbitrary per-page host or a value taken from a client Host/query.

An active administrator of the same tenant must explicitly activate its own custom domain. Before the switch, validate current membership, binding ownership, verified active binding, valid TLS, tenant/site eligibility and equivalent eligible published pages/locales. Domain entry or verification alone does not activate it. On success the custom domain becomes primary/canonical; public-page GET/HEAD requests to the Godent alias return **301** directly to the equivalent page on that primary. Strip only the platform tenant prefix, retaining site-page and same-language suffix. Never map everything to the homepage, another tenant or a draft. Genuinely missing, withdrawn or unpublished resources without an eligible Published fallback retain safe non-public/not-found handling, never a homepage catchall. Missing translation alone follows the Published VI fallback contract, not an automatic 404.

Activation is routing configuration, not content publication or patient-content review. It does not create a second tenant/site/content/media/publication/lead list, publish pending drafts or rewrite immutable snapshot history. Current primary/delivery mapping applies consistently to the eligible published snapshot. During activation, publish/unpublish, membership/binding changes and retries, revalidate the current mapping/publication context and fail safely on conflicts rather than emit mixed-primary output or resurrect withdrawn content. Cache keys/invalidation cover the primary/mapping revision and URL-dependent outputs; jobs bind stable tenant/site/resource identities and recheck current mapping/eligibility. Exact transaction/schema mechanics remain future implementation details.

Primary pages self-reference with absolute canonicals. Navigation, sitemap, hreflang, metadata/social URLs and eligible structured data agree with the current primary and actual eligible published language. Missing translation uses Published VI/default fallback under workflows. Exact page/field fallback and requested-URL versus redirect/canonical/hreflang mechanics remain a bounded contract before localized implementation: never claim an EN alternate/canonical merely because an EN request delivered VI, expose drafts/revoked media or invent public content. This does not change ADR-004’s cross-entry primary/301 policy. Do not robots-block/noindex aliases to force canonical selection. Canonical omits tracking; redirects may retain safe allowlisted tracking parameters. Functional queries need explicit semantics rather than indiscriminate removal. Only validated current bindings may supply redirect destinations: deny forged hosts, unverified/inactive bindings or stale bindings after reassignment, cross-tenant redirects, loops and chains.

This 301 rule applies only to public **GET/HEAD page aliases**. API, admin, authorized private preview, media and intake POST keep their dedicated contracts; never blanket-redirect them or replay POST. Both valid intake entries retain the common tenant lead list and existing tenant-scoped 24-hour idempotency. Media access and current revocation do not become page redirects or permanent public bucket grants.

Temporary DNS/TLS failure does not automatically change primary/canonical or create a reverse 301. Cached permanent redirects mean the Godent alias is not a guaranteed instant emergency fallback after activation. Controlled manual migration/reverification/equivalent-page mapping, no automatic outage flip and no reuse of old binding are accepted. Detailed removal/replacement/reactivation/renewal/failure mechanics still need a technical contract. Exact locale syntax, reserved names/slug lifecycle and DNS/TLS providers/setup remain deferred, not the approved primary/301 policy. Domain registration is human-reported and no DNS/TLS or live serving has been tested.

- The minimal product actors are platform administrator, active tenant administrator and anonymous visitor. [Access control](access-control.md) is canonical. All active tenant administrators manage all their tenant's content and leads; assignment/location do not reduce that access.
- Authenticate and authorize tenant/resource/action before returning reads, writes, lists, counts, search, exports, suggestions or caches. Do not trust client tenant IDs or stale membership claims. Same-tenant grants cannot create platform authority or grant another tenant.
- Use tenant keys, tenant-consistent foreign keys/uniqueness and PostgreSQL row-level security. Runtime roles must not own protected tables or have superuser/BYPASSRLS privilege; keep migration/operational credentials separate and apply FORCE ROW LEVEL SECURITY where appropriate.
- Bind validated tenant context inside each transaction, including repository calls; prove cleanup across pooled connections, rollback, exceptions and concurrent tenants. Workers use the same tenant boundary and recheck current eligibility before sensitive effects.
- Platform operations confer no blanket tenant-private-lead access or impersonation. No elaborate support-access approval workflow is selected; a future private-data support mechanism needs specific authority.
- Resolve public websites through the canonical platform-path/custom-host contract above. On godent.vn validate the registered tenant prefix; on a custom host use its verified active binding without treating the first path segment as another tenant selector. Trust forwarded headers only from the confirmed proxy path. Slug/host uniqueness, namespace reservation, current mapping and safe removal/reassignment prevent tenant takeover and stale routing.
- Administration follows the approved local endpoints and approved S02 D10 session/CORS/CSRF contract; cookies are not port-isolated. Dedicated cms.godent.vn is a production-only proposal, not local topology or verified DNS. Production public custom domains do not receive admin sessions; neither origin checks nor port separation substitutes for authorization or intake abuse protection.
- Public reads expose only currently eligible publication snapshots/derivatives. Draft preview requires current tenant-administrator authorization, stays private and must not enter public caches or indexes.
- Cache identity/invalidation covers tenant/site, locale, route, publication/configuration and current mapping identity/revision, plus entry origin/base for URL-dependent output; prove slug/domain removal/reassignment, unpublish and revocation across both entries and HTML, navigation, SEO and media delivery. Multi-instance consistency needs proof before adopting multiple instances.
- Filter/sort/page at the data source with bounds, allowlists and stable tie-breakers. Lead queries are tenant-wide, never location permission queues. Define Vietnamese normalization/search expectations before fuzzy matching or an external engine.
- Prices use exact numeric representation, currency/unit and documented rounding. Separate absolute instants from business dates/promotion validity; apply the configured tenant timezone for display.
- Persist lead and durable notification intent before acknowledgement. Intake idempotency, expiry and private notifications follow [workflows](workflows.md#consultation-intake-and-notifications); no appointment is confirmed.
- Audit important actions with redacted actor/time/object/change evidence. Approved D4 retention/withdrawal targets are canonical in workflows, not a legal compliance claim.

## Publication and media consistency

Exactly Draft → Published. The same tenant administrator writes and publishes; there is no clinical reviewer or mandatory review stage. A current public pointer defines Published, even with a pending draft. Without that pointer the item is Draft. Save never changes live output; unpublish removes the pointer/eligibility; restoration creates a draft for the administrator's explicit publish.

Publish validates expected versions, tenant-consistent references and current media permission, then atomically captures the immutable snapshot/reference closure and pointer with durable delivery intent. [Workflows](workflows.md#immutable-publication-closure-and-current-eligibility) defines the closure; ordinary mutable service/price/doctor/location/media/configuration lookups cannot leak later drafts into public output. Reject optimistic save/publish conflicts rather than overwrite another administrator.

Current eligibility overrides immutable history. Private originals and patient-derived publication permission remain protected without a clinical editorial gate. Withdrawal immediately blocks eligibility; delivery/purge targets and asynchronous pending/failed/retry handling follow [media workflow](workflows.md#media-publication-permission-and-withdrawal). Never report failed purge as completed or let a stale retry regrant public permission.
